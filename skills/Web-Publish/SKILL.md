# Web-Publish

Web-Plan(필요하면 Web-DeepSearch, Web-BM)으로 정리된 웹서비스 기획 내용을 노션 데이터베이스에 페이지로 발행하는 스킬.

공통 절차는 `../references/notion-publish-workflow.md`를 읽고 따른다.

## 데이터베이스

이름: **웹서비스 기획 아카이브**. 없으면 아래 스키마로 만든다.

```
CREATE TABLE ("이름" TITLE, "상태" SELECT('아이디어':gray,'초안':yellow,'진행중':blue,'완료':green), "카테고리" SELECT('SaaS':blue,'커머스':orange,'커뮤니티':purple,'크리에이터툴':pink,'관리자툴':gray,'기타':default), "BM 한줄요약" RICH_TEXT)
```

카테고리가 후보에 없는 서비스면 "기타"를 쓰고, 필요하면 옵션을 새로 추가해도 된다.

## 페이지 구조

`../references/web-service.md`의 섹션 순서를 따르되 노션 문법으로 다시 표현한다:

- 1~3번(개요, 타겟, 핵심 기능)은 페이지를 열었을 때 바로 보이게 그대로 둔다
- 8번(수익화/BM)은 콜아웃 블록으로 강조한다
- 3번 기능 우선순위 표, 6번 기능 명세(있다면)는 노션 테이블로 만든다
- 7번(비기능 요구사항), 10번(경쟁 서비스)처럼 매번 볼 필요는 없는 섹션은 토글로 접는다

**토글/콜아웃/표는 담는 그릇만 바꾸는 것이지, 내용을 줄이는 게 아니다.** 특히 6번 기능 명세의 완료조건(체크리스트)처럼 구체적인 내용은 노션으로 옮길 때도 항목 하나하나 그대로 옮긴다 — "주요 내용만 요약해서 콜아웃 하나로 정리" 같은 식으로 압축하지 않는다. 토글로 접는다고 해서 그 안의 텍스트 양을 줄여도 되는 게 아니다 — 접혀 있을 뿐 펼치면 원래 분량 그대로여야 한다. 노션 페이지가 원본 마크다운보다 내용이 적다면 잘못 옮긴 것이다.

## 올리기 전에 문체를 한 번 훑는다

페이지 내용을 다 쓴 뒤, 노션에 올리기 직전에 `../references/natural-writing.md` 체크리스트로 한 번 훑는다. 새 호출이나 별도 도구 없이, 방금 쓴 문장 중 기계적으로 반복되거나 클리셰인 부분만 그 자리에서 고친다 — 표/콜아웃/토글 구조는 건드리지 않는다.

## 완료 후

생성된 노션 페이지 URL을 사용자에게 알려준다. 이후 내용이 바뀌면 새로 만들지 말고 같은 페이지를 업데이트한다.
